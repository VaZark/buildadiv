Manual playground

One scenario per runtime behavior. Follow the steps, compare with “Expect”, and keep the browser console open. Server request counts and document events update on the right.

1 · A trigger refreshes fresh data

  1. Note the /api/products count.
  2. Click Refresh products, then Refresh counts.

Expect: the count rises by one per click, although the cached data never goes stale.

2 · Delete with a string id from data-key

  1. Click Delete on a row.

Expect: the row disappears from this list and from scenario 1, because { id: '2' } invalidates the cached item with numeric id 2. Use Reset demo data to restore it.

3 · Select a page while another loads

  1. Click Page 2 and then, within a second, Page 5.

Expect: “Page 2” flashes, “Loading…” returns, and “Page 5” stays. After Refresh counts, both page=2 and page=5 are listed; the second click is never dropped.

4 · Context runs in every state

  1. Click Reload status and watch the text while it loads.

Expect: “waiting for the server”, then “loaded with HTTP 200”. The failing request shows its own context hint: “The server answered 500”.

5 · A throwing context function is contained

  1. Click Reload careless.

Expect: the region still shows “0 fields”. The console shows one reported TypeError per request (from the pending state), and the event log shows loadCareless:success, not error.

6 · A broken template does not fail the request

  1. Click Reload rows.

Expect: the healthy region shows the product count. The console reports “List keys must be unique” from the broken region, and the event log shows loadBrokenRows:success with no error.
