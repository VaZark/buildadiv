2 · Lists and nested templates

data-accepts="array" stamps one row per order, keyed by id. Inside each row, two nested templates list the order's tags (an array of strings) and its line items (data-from="order.items"). data-if / data-if-not switch per-row content. This region shares section 1's loadOrders request. Mark shipped calls a mutation whose response is reconciled into the cache: only that row updates, without refetching.

3 · subscribe vs load

Both lists start from the same loadOrders data. A subscribe region is mounted: reconciliation, invalidation and freshness keep it current. A load region calls the action once, renders the result and stops listening.

  1. Mark shipped on an order in section 2: reconciled, no request.

7 · Filters

A binding is a path plus filters, applied left to right: path | filter | filter:arg. Only fallback is built in; this page registers the provided filters and one of its own with configure({ filters }). Formatting is always locale-aware. The locale is the filter's own last argument (number:de-DE), else configure({ locale }), else the element's nearest lang (this page: en), else the browser's default. A currency is named (currency:EUR) or configured. The builder runs the same functions for {{ }}, using the language of the page it builds.
