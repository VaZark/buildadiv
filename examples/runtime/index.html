2 · Lists and nested templates

data-accepts="array" stamps one row per order, keyed by id. Inside each row, two nested templates list the order's tags (an array of strings) and its line items (data-from="order.items"). data-if / data-if-not switch per-row content. This region shares section 1's loadOrders request. Mark shipped calls a mutation whose response is reconciled into the cache: only that row updates, without refetching.

3 · subscribe-to-action vs load-from-action

Both lists start from the same loadOrders data. A subscribe-to-action region is mounted: reconciliation, invalidation and freshness keep it current. A load-from-action region calls the action once, renders the result and stops listening.

  1. Mark shipped on an order in section 2: reconciled, no request.
  2. Reopen all orders: the Order tag is invalidated and subscribed regions refetch.

4 · Pagination: one page at a time

paginated: { mode: 'pages' }. Next is a plain data-action (it loads the next page); Previous passes a page number from a listener. data-if hides each button at the ends.

5 · Pagination: infinite list

paginated: { mode: 'infinite' } with a merge function for the { items, page, pages } envelope. There's deliberately no on-pending: the first placeholder is the element's own content, and the list stays on screen while more items load.
